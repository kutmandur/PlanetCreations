# PlanetCreations 1.0.37 — Reliable desktop sessions and community showcases

This release makes the hosted desktop experience more resilient, introduces community showcase control for the in-game overlay, and modernizes public navigation and administration.

## Reliable desktop connectivity

- Desktop sign-in no longer enters a bounded App Check reload loop when reCAPTCHA attestation is throttled.
- App Check remains enabled and retries a rejected authentication token once without navigating away from the login form.
- The hosted Offline Manager keeps probing indefinitely and returns from its bundled fallback as soon as the website is reachable again.
- Recovery continues even if the bundled fallback itself fails to load, with retries capped at a 60-second interval rather than a maximum attempt count.
- Hidden tray windows keep Firebase heartbeats, authentication refreshes and network events active instead of being background-throttled.
- Foregrounding the client or opening the overlay immediately retries an active hosted fallback, while aborted navigations and delayed compatibility handshakes no longer disconnect a valid session.
- Desktop authentication is shared between the main window and in-game overlay.

## Community showcase overlay

- Community managers can launch a Creation or a configured group of Creations directly in a connected desktop overlay.
- Group showcases provide Creation selection, sorting, verified park and blueprint details, ride checklists and the active sharing QR code.
- Finishing a showcase clears its overlay state and restores the normal overlay experience.
- Stream Management stays docked beside the expanded overlay and follows its visibility and bounds.

## Routes, sharing and administration

- Hosted web pages now use native root-relative routes, while packaged `file://` builds retain hash routing and legacy public hash links are migrated automatically.
- Communities support root-level vanity URLs, with the previous `/community/<slug>` form retained as an alias and reserved slugs protected consistently in the app and Firestore rules.
- Creation share previews retain their server-rendered Open Graph route for crawler-compatible metadata.
- Admin and moderation navigation is consolidated, with updated tab controls and management layouts.
- Client download recommendations better match the visitor's platform and architecture.

## Release integrity and compatibility

- macOS release builds now require Developer ID signing and notarization credentials; missing credentials fail the job instead of publishing an unsigned artifact.
- A separate verification workflow can validate macOS packaging from branches or release tags, including compatibility with legacy build scripts.
- The hosted Workshop minimum bridge version remains unchanged because these changes preserve released native contracts and use capability detection.
- The Microsoft Store package is intentionally not built by this GitHub release workflow.
